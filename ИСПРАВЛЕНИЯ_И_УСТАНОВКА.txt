ИСПРАВЛЕНИЯ И ОБЯЗАТЕЛЬНАЯ НАСТРОЙКА SUPABASE

Что исправлено:
- Исправлены проверки доступа к загрузкам: проект использует profiles.id, поэтому теперь правила Storage проверяют current_profile_id(), а не auth.uid(). Это была одна из причин отказа при публикации постов/историй.
- Добавлен единый SQL для таблиц stories, posts, post_likes, post_comments, bucket-ов и правил доступа.
- Добавлены лайки, снятие лайка, комментарии и удаление собственных комментариев/постов.
- Ошибки ленты и историй теперь показывают причину, а не только общий текст.
- В ленте обновлён интерфейс в стиле VK.
- Разделы «Данные и память», «Папки с чатами», «Энергосбережение», «Язык» получили рабочие локальные настройки; «Ключи доступа» ведут в экран безопасности.
- Видеоистории отображаются как видео и в списке историй.

ОБЯЗАТЕЛЬНО СДЕЛАЙ ЭТО ОДИН РАЗ:
1. Открой сайт https://supabase.com/dashboard и выбери проект, к которому подключён сайт.
2. Слева открой SQL Editor.
3. Нажми New query.
4. Открой файл SUPABASE_SETUP.sql из этой папки, скопируй ВЕСЬ его текст.
5. Вставь текст в SQL Editor и нажми Run.
6. Дождись сообщения об успешном выполнении. После этого обнови сайт (Ctrl+F5) и попробуй опубликовать пост и историю.

ВАЖНО:
- Не удаляй старые таблицы и не запускай DROP TABLE.
- SQL написан с CREATE/ALTER IF NOT EXISTS и DROP POLICY IF EXISTS; он добавляет недостающие таблицы/права, не удаляя опубликованные посты и истории.
- Папки чатов, настройка языка и уменьшение анимаций пока сохраняются на этом устройстве. Полный перевод всех экранов и подключение папок к фильтрации списка чатов — отдельный следующий этап.
- Камера в браузере требует разрешения и обычно работает на HTTPS или localhost.

ПРОВЕРКА:
- TypeScript: npm run typecheck — успешно.
- ESLint для изменённых файлов — успешно.
- Полная сборка Vite в этой среде не завершилась: в предоставленном node_modules отсутствует необязательный бинарный пакет Rollup для Linux. На твоём компьютере после npm install это должно установиться автоматически.
